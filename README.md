# Track

A calm daily task, habit and goal tracker — "plan less, finish more." Built with
Flutter, all data stored locally on-device (`shared_preferences`), with local
notifications for daily nudges and event reminders.

This is a from-scratch Flutter rewrite of an earlier single-file HTML/JS
prototype. It was written in an environment **without the Flutter SDK
installed**, so the Dart source has not been compiled, run, or analyzed —
see "Known limitations" below before you rely on it.

## Getting started

This repo currently contains only the Dart source (`lib/`) and `pubspec.yaml`
— no `android/`, `ios/`, `web/`, etc. Those platform folders are generated by
the Flutter tool itself and are version/SDK-specific, so hand-writing them
without being able to run `flutter create` would be more likely to introduce
bugs than to help. Generate them locally instead:

```bash
flutter create .          # adds android/, ios/, and other platform folders
                           # in place, without touching lib/ or pubspec.yaml
flutter pub get
flutter run
```

If `flutter create .` complains about the existing `pubspec.yaml`/`lib`, that's
expected — it will merge in the missing platform directories and leave your
source alone.

### Notification setup (after `flutter create .`)

Reminders and event alerts use `flutter_local_notifications`. The plugin needs
a couple of manual platform tweaks that `flutter create` won't add for you:

- **Android**: in `android/app/src/main/AndroidManifest.xml`, make sure
  `POST_NOTIFICATIONS` (Android 13+) and, if you want exact-time firing,
  `SCHEDULE_EXACT_ALARM` permissions are declared. The app requests the
  runtime notification permission itself (Settings → reminders toggle).
- **iOS**: no extra Info.plist entries are required for local notifications;
  the app requests permission at runtime via the reminders toggle.
- Both platforms: if notification icons/sounds don't matter yet, the
  defaults (`@mipmap/ic_launcher` on Android, system default on iOS) are
  fine to ship with.

App icon and splash screen are left as Flutter's defaults — swap them with
`flutter_launcher_icons` / `flutter_native_splash` (or manually) once you have
real artwork; this environment had no way to generate or verify image assets.

## What's implemented

Mapped to the original feature request list:

1. **Onboarding** — `lib/screens/onboarding_screen.dart`. First-run flow:
   welcome → name → main goals → daily task limit → focus style → summary.
   Sets the daily Sooner-bucket limit instead of it being a hardcoded `5`.
2. **Today page hierarchy** — `lib/screens/today_screen.dart`. Greeting +
   "N tasks left today" hero + Start Focus button, a numbered "Today's
   priorities" list, a collapsed "Completed today" section, then "Later".
3. **Task editing** — long-press any task to open `TaskSheet` in edit mode
   (rename, difficulty, category, bucket, due date, delete).
4. **Due dates on Later tasks** — `TaskItem.dueDate`, set from the add/edit
   sheet, shown as "Due: Aug 1" on the task tile.
5. **Statistics** — `lib/screens/progress_screen.dart` ("Progress" tab):
   weekly completed count, best day, average/day, top category, and a
   per-category breakdown.
6. **Categories** — `TaskCategory` enum (Study/Health/Work/Personal/Other),
   set per task, feeds the Progress page's category breakdown.
7. **Recurring tasks** — `RecurringTemplate` + `RecurrenceRule` in
   `lib/models.dart`, generated into real `TaskItem`s each day by
   `AppState.ensureRecurringInstances()`. Set via the "Repeat" picker when
   adding a task (Once / Daily / Weekly with day picker).
8. **Focus mode + Pomodoro** — `lib/screens/focus_screen.dart`: countdown
   timer (length from your chosen focus style), Start/Pause/Reset, plus the
   original mark-done / working-on-it / skip flow.
9. **Backup** (client-side only, no accounts/cloud — see limitations) —
   Goals tab → Backup card. Export copies a JSON snapshot to the clipboard;
   Import parses pasted JSON back in, replacing local data after a
   confirmation.
10. **"Mobile app experience"** — for a native Flutter app this is offline
    local storage (inherent, no network calls at all) + local notifications
    for reminders. There's no PWA install-prompt equivalent since this isn't
    a web app; app icon/splash are Flutter defaults, see above.
11. **Animations** — `FadeSlideIn` (entrance) and `PopOnChange` (status-chip
    check pop) in `lib/widgets/common.dart`, an animated stacked progress
    bar, `AnimatedCrossFade` for project expand/collapse.
12. **Technical fixes**:
    - **Sorting**: `AppState.sortTasks()` — status (working → pending → done)
      then difficulty (hard → normal → easy).
    - **Validation**: `AppState.validateTaskText()` — minimum 3 characters,
      requires at least one letter/digit (rejects emoji-only/symbol-only),
      duplicate-in-bucket warning with an "add anyway" override.
    - **History memory**: "Clear history" action on the Goals page's past
      weeks/months, plus the export/import backup as a real data safety net.
13. **Daily review** — evening card on the Today page (after 5pm, once/day):
    mood (😞/🙂/🔥) + a short reflection note, stored per day.
14. **AI task breakdown** — intentionally **not implemented**. It needs a
    real LLM API call, which is a backend dependency out of scope for this
    pass (agreed with the requester up front).

### Also intentionally dropped for scope

Two features from the original HTML prototype were **not** carried over,
to keep this rewrite focused on the 14 requested improvements:

- Linking a task to a project (`task.projectId` in the old app) — the
  Projects tab already covers project-specific checklists on its own.
- The "Hybrid Athlete plan" one-tap seed data (a personal training-plan
  preset baked into the old prototype) — unrelated to the feature list and
  easy to re-add later as a similar `seedXPlan()` helper in `AppState` if
  wanted.

## Known limitations (read before shipping)

- **Unverified**: written without a Flutter SDK available to run
  `flutter analyze` / `flutter run` / `flutter build`. Treat the first build
  as a real test pass, not a formality — skim `flutter analyze` output for
  anything this review missed, especially around `flutter_local_notifications`
  (the API surface is the least certain part of this codebase since it's the
  most version-sensitive dependency).
- No accounts, login, or real cloud sync — export/import JSON is the backup
  story, per the client-side-only scope agreed for this pass.
- No AI features.
- Platform folders (`android/`, `ios/`, …) aren't in this repo yet — see
  "Getting started".
